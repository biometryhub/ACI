01

Why this document exists

Two documents accompany this package. The companion answers whether the numbers are right. This one answers how the software came to be: which choices were deliberate, what was weighed and set aside, what the defects turned out to teach, and which questions are still open.

It is written for someone deciding whether to build on the package or to work on it, rather than for someone using it. A reader who wants to know what the software does should start with its articles. A reader who works on scientific software of any kind may find the middle sections useful on their own terms, because the verification problem this package ran into is general and the vocabulary for it is older and better developed than the software itself.

02

The method, and why it needed reimplementing

Assimilative causal inference asks how much the future of an observed signal tells you about the present state of something you cannot observe. For a conditional Gaussian nonlinear system, a class in which the statistics of the unobserved component conditional on the observed path stay Gaussian, the two posteriors involved are available in closed form: a forward filter that has seen the record up to now, and a backward smoother that has seen all of it. The relative entropy between them, also called the Kullback-Leibler divergence, evaluated at each instant, is the causal-information metric. A second quantity, the causal influence range, measures how far ahead one must look before that answer stops changing. The method is due to Andreou, Chen and Bollt, published in 2026.

The authors publish their code, which is more than most methods papers do. What they publish is seven top-to-bottom MATLAB scripts totalling 12,339 lines, of which exactly two files are callable functions, and both of those are third-party utilities rather than the authors' own work. Running the method on a new dataset therefore means reading someone else's script and retyping its algebra, and every reader who does that produces a private, unchecked reimplementation.

This package makes the method callable, with its mathematical preconditions enforced rather than assumed, and with a stated account of what its evidence covers. It has two dependencies, graphics and stats, both shipped with R.

03

Conceptual genesis: a program with no oracle

Software testing calls the source that decides whether an output is correct a test oracle, and the difficulty of obtaining one is known as the oracle problem, surveyed by Barr and colleagues. Ordinary software usually has an oracle close at hand, because someone knows what the answer should be. A program written to compute something that is not otherwise known does not. Weyuker named these non-testable programs and observed that much scientific software belongs to the class, since the program exists precisely because the answer is unavailable by other means.

Two established strategies address this. The first is a pseudo-oracle: an independent implementation of the same specification, used in place of a true oracle, proposed by Davis and Weyuker. The second is a metamorphic relation: a property the output must satisfy that can be checked without knowing the correct answer, surveyed by Segura and colleagues. Both are available here, and both are used.

The pseudo-oracle carries a caveat that turned out to shape this whole package. Knight and Leveson tested the assumption that independently written versions of a program fail independently, and found that they do not: common failures occurred far more often than an independence assumption predicts, because different people make the same mistakes on the same hard parts. If that holds for versions written by different people, then two versions written by the same person offer no independence to appeal to at all. A reimplementation checked against fixtures its own author transcribed can demonstrate self-consistency and nothing more: if the author misread an equation, the fixture encodes the same misreading and passes.

That observation is the origin of the package's organising rule, and of a word this document uses throughout. An oracle is grounded when its expected values come from a source that did not also produce the code under test. It is not a term of art, and it is used here because the distinction it names is the one that kept mattering.

One further distinction sets the scope. Oberkampf and Roy separate verification, which asks whether the equations are being solved correctly, from validation, which asks whether they are the right equations for the phenomenon. This package is a verification exercise throughout. Whether assimilative causal inference is the right way to ask a causal question of a physical system is the method's own claim, argued in the paper that introduced it, and the package's articles are careful to say which of the two a reader is being offered.

Two consequences followed for how the package was built. Capability was allowed to arrive only with its grading, or with an explicit declaration that it was ungraded, and that rule is enforced by the test suite rather than remembered. The ordering of the first two commits records the same priority: the oracle harness and its fixtures were built and committed before the package was scaffolded.

04

Design decisions, and the alternatives set aside

Twelve decisions are recorded in the repository, each in a fixed shape: what was decided and when, which alternatives were considered, why each was rejected, and what the decision will cost in future. The rejected alternatives are the part worth reading, since several of them are reasonable and a different project would choose differently. Six are set out below. The rest are in the index at the end.

Reference kernels become callable by byte-verified hoist, and the generated files are not committed

To run the authors' algebra on data other than their own, their computational passages have to become functions. They are hoisted rather than retyped: each generated function is a signature, a byte-exact slice of the reference between explicit markers, and an end. A checker re-reads the slice from source and fails on a single byte of drift, and separately refuses any executable line outside the markers.

Set aside: keeping the hand-transcribed harnesses, which are the reason the work exists; re-implementing the kernels in MATLAB from the paper, which would have looked the most professional while grading nothing, since a third implementation by the same author is a third opportunity for the same misreading; committing the generated files, permitted by the upstream licence but inconsistent with treating the reference as re-clonable; and refactoring the reference scripts in place, which destroys the thing being verified, because once the file is edited "byte-identical to the reference" has no referent.

Forward costEach further model costs a manifest record per kernel and a gate run. An upstream re-clone must be followed by the byte check, which fails loudly if line numbering has moved.

Reference workspaces are captured under a machine-verified minimal substitution

The plan had said "run the original script unmodified". That is not available: at its published settings the dyad script allocates a 20601 × 20601 matrix of 3.40 GB and three online-smoother triangles of roughly 10.8 GB. The problem size is therefore reduced by substitutions declared in a manifest, and a tool asserts before the run that the substitution is minimal, meaning nothing is changed beyond the declared knobs.

Set aside: running unmodified and waiting, the honest ideal but not reachable on available hardware; capturing a cheap prefix with a debugger breakpoint; reducing the size without verifying minimality, which would leave the trusted side of the comparison unaudited; and abandoning workspace capture entirely.

Forward costEach new script needs a knobs record with a justification and a list of conditions that must hold after substitution. Those conditions earned their place on the first run, when a reduced profile turned out to have a reporting window shorter than the lookahead it was measured against.

Scripts that collide on variable names are composed section by section

The predator-prey script cannot be run top to bottom without silently producing wrong results. It carries fourteen blocks headed "run this code section to study the causal relationship", seven for each causal direction, and every block assigns the same names. The filter mean is written for direction one and overwritten by direction two before anything consumes it, so a whole-script run computes direction one's smoother from direction two's filter. Nothing raises, and the numbers look plausible. Each direction is therefore composed from its own declared line ranges, guarded by a condition that holds in one direction only.

This is not a defect in the reference when it is used as documented, since its own banners tell the reader to run one section at a time. It is a hazard for anyone automating it, and the dyad's linear structure makes whole-script capture look like the general case when it is not.

Forward costEvery further script must be inspected for name collisions before a profile is declared. The five scripts of the climate case study are each around two thousand lines, and the same pattern would be easy to miss.

The online smoother reconstructs its update products in logarithms

The reference stores the fixed-lag online smoother as nested staggered arrays, one row per observation, each row holding an estimate at every earlier instant. That is quadratic in the record and cannot run at the scale of the published figure on ordinary hardware. The implementation accumulates the ordered products of the per-step factors in logarithms and truncates them once they fall below tolerance, which bounds the work by the effective lag and keeps the memory linear in the signal.

The redesign is graded rather than assumed. A literal transcription of the reference triangle is kept permanently in the test suite and the fast path is checked against it, agreeing to 2.4e-15 at 400 steps. That test is slow by design and is documented as not removable for being slow.

Forward costThe reduction is one-dimensional. Matrices do not commute, so the vector implementation keeps the geometric truncation but not the logarithmic reconstruction.

The package stays pure R

Compiled kernels were adopted for the quadratic recursion and the three-million-step climate filter, and the decision was reversed the same day when two constraints landed together: the package targets CRAN first, and reproduction at published scale moves to a companion repository rather than living in the package. Both halves of the original justification left the package with that second constraint.

Forward costThe pure-R ceiling is now an accepted limit. The published influence-range figure is a batch computation rather than an interactive one, documented in the function rather than guarded in code. Whatever reproduces the climate case study at full resolution inherits the performance problem.

An unresolved influence range is reported as a bound, not as missing

A time near the end of a record cannot have its influence range resolved, because the observations that would settle it do not exist. Such a time yields a small number that reads as a confident short range. The package first returned NA there. It now returns the computed value as a right-censored lower bound, borrowing the term from survival analysis, where a censored observation is one known only to exceed some value, with the caveat carried in a four-valued status field. The reasoning is that a range consuming most of the available record is not an absent measurement but a censored one. Only the case with fewer than three later observations, where no quadrature exists, still returns NA.

Set aside: keeping NA; returning the value with no flag, as the reference does; dropping the older saturated field rather than defining it in terms of the new status, which would have broken callers for tidiness.

Forward costThe margin that decides censoring defaults to 0.1, a judgement rather than a calibrated constant. It is documented as this package's own device, and it is the principal reason the function is marked experimental. Calibrating it is one of the open problems below.

The development cycle

Thirty-five commits between 11 July and 15 August 2026, reconstructed from the repository history rather than from recollection, so a reader with the repository can check it.

11 July · before the package

The oracle harness, then the scaffold

A MATLAB harness reproducing the deterministic core of the reference, its fixtures, and a validated dyad calculation, all committed before the package existed. The release candidate followed in the next commit.

Contracts, and the first gap in the evidence

Inputs that previously produced missing values or low-level errors became explicit rejections naming the argument and index. A second fixture was added for the noise cross-covariance path, because every scalar model in the reference sets that covariance to zero and so exercised those terms without ever grading them. A review round then corrected a diagnostic that miscounted, split a figure whose two series shared an axis they had no business sharing, and carried the upstream copyright into the licence files.

13 August · capability

Nine commits in one day

The causal influence range, a latent self-drift that may depend on the observed state, the noisy predator-prey model in both causal directions, vector-valued states, the conditional construction, a Milstein scheme for diffusion that varies with the state it integrates, the stochastic climate model, and the register that gates the build. Capability and its grading were never separated by more than a day.

14 August · parity

Graded against the authors' code, not against a transcription

The hoisting instrument, extended across three of the reference's systems, and with it the first grading of the influence range that did not share a convention with the thing under test. A second review round followed, and 0.2.0 closed it.

15 August · 0.2.1

Documentation

The articles typeset their mathematics at the size of the surrounding text, and without fetching anything from the network.

Two patterns are visible in retrospect. Both review rounds produced corrections to claims already made in writing, rather than only to code, which is what led to the claim-checking test described below. The largest single advance, grading against the authors' own code, came from noticing that a strong-looking agreement had been measured against a harness sharing the convention under test.

06

How the package is graded

The suite is 736 tests across 23 files with no skips, and R CMD check --as-cran reports no errors and no warnings. Volume is the least interesting property of a test suite, so what follows is what the tests are checked against, in the vocabulary of section three.

Three oracles, of three different kinds

The first is a grounded oracle: the authors' own dyad calculation, at their published parameters and seed. The second is a pseudo-oracle in Davis and Weyuker's sense, a harness with correlated noise switched on. It has no upstream counterpart, because no scalar model in the reference exercises a non-zero noise cross-covariance, so it is a second independent implementation of the published equations in a different language and runtime. It is deliberately not described as grounded: the same person wrote both sides, which is the situation Knight and Leveson's result warns about. What it establishes is narrower and still worth having, namely that a transcription slip on the R side would have shown up across a full transient.

The third kind depends on no implementation at all. For a constant-coefficient system the stationary filtered covariance is the positive root of an algebraic Riccati equation, a standard object in linear filtering. Started at that root, the recursion must stay there. Two further identities are checked in the same spirit: the smoother equals the filter at the final step by construction, and with no coupling the metric must vanish. These are metamorphic relations, and they are grounded in the strongest sense available, because they follow from the governing equations rather than from anyone's code. Each fixture records, in a committed manifest, both what it grades and what it does not.

A register that fails the build on an undeclared gap

A term can be publicly reachable, execute on every run, be reported as covered by line coverage, and be graded by an oracle, while still being checked against nothing, because the fixture that grades it multiplies it by zero. The response was not a note to remember. The suite holds a register that reads which components each oracle actually exercises, and the build fails when a capability appears that is neither graded nor declared ungraded.

Parity against the reference itself

Each hoisted function is called with the inputs the script itself used, and every output must equal, not approximate, the value the script produced. That gate stands at 124 of 124 outputs across five profiles at a maximum absolute difference of exactly zero, over 1,681 verbatim reference lines in 25 extracts. Against that instrument the package's scalar core agrees on 26 of 26 quantities across two datasets, worst case 1.5e-14. The committed dyad fixture was re-graded at the published record length and agreed with the authors' output at a difference of exactly zero, which retired a standing doubt about the transcription rather than confirming one.

For scale: Hatton's T2 experiment measured independently developed implementations of the same algorithms, run on the same input data with the same parameters, and found agreement "gradually degenerated from 6 significant figures to 1 significant figure during the computation". Against that baseline, agreement at 1e-14 between an R implementation and the authors' MATLAB is not a routine outcome, and no comparison here returned exact equality between the two languages, which is itself the evidence that both sides genuinely execute. Two independent implementations agreeing bit for bit would mean one of them had not run.

07

Implementation patterns

Relative entropy evaluated without cancellation

The dispersion term of the Gaussian relative entropy subtracts two nearly equal quantities. Written directly it loses the value precisely where the metric is smallest: at a covariance ratio of 1 + 1e-12 it returns zero where the correct value is 2.5e-25. Writing the ratio as 1 + d and expanding in that form keeps it. Values at the round-off floor are clamped within a documented tolerance, and anything more negative is an error rather than a result.

Dispatch on the shape of the components

Vector states were added beside the scalar implementation rather than replacing it. A matrix latent-noise covariance selects the vector path and a bare number the scalar one. At one dimension the two agree bit for bit, which is tested, but the scalar recursion is around thirty times faster and is what the oldest oracle grades. Replacing it would have spent a validated asset to buy nothing.

Failing closed on the covariance

An explicit Euler scheme can drive a posterior covariance out of its domain when the step is too large for the system, even though the model itself is admissible, and the relative entropy that scores the result has no meaning in that state. The filter and smoother check at every step and stop at the first value that is not finite and strictly positive, naming the algorithm, the index, the time and the value. In the vector case positive-definiteness is checked by attempting a Cholesky factorisation rather than by a proxy for it, and the relative entropy is evaluated through Cholesky factors rather than an explicit inverse or a determinant formed as a product.

Comparison criteria that survive a zero crossing

The parity harness's first full run reported one quantity out of tolerance at a relative error of 4.2e-11. The maximum sat at the only point in a 3,001-step series with magnitude below 1e-3, against a series median of 0.864, where the absolute difference was 7.0e-15. The problem was in the criterion rather than in either implementation: a purely relative test divides by the value, so at a zero crossing it divides by nothing in particular. The criterion is now mixed, absolute plus relative, with every relative tolerance left where it was, and each comparison reports how much of its permitted budget the worst element consumed.

08

What the failures taught

Five defects are worth recording because each one produced a piece of knowledge that changed how the package is checked. They are stated lesson-first, since the lesson is the part that transfers.

Coverage and an oracle can both be satisfied by a path checked against nothing

Line coverage was total and the oracle agreed to 1e-14, while the noise cross-covariance terms had never been compared with anything. Every scalar model in the reference sets that covariance to zero, so the terms ran on every fixture and were multiplied by zero. The remedy was the second harness, the analytic identities, and the build-gating register.

An oracle's scope is a claim in its own right, and needs measuring rather than asserting. A high coverage figure sitting beside a graded oracle can manufacture confidence in an ungraded path.

Accepting an input's shape is not the same as consuming it

A three-dimensional observation-noise covariance that changed over the record produced a result identical, to the last bit, to a constant one: the schema accepted the array and inverted only its first slice. Nothing caught it. Not the oracles, whose fixtures held that covariance constant; not the contracts, which accepted the array; not line coverage, which was total.

The general property is cheap to test and the instance is not: a coefficient is genuinely consumed only if perturbing it at a late step changes the answer. The register now tests that, rather than testing the one case that was found.

An argument is not a measurement

The objective influence range differed from the reference by 4.58e-09, and the quadrature-closure explanation had been considered and dismissed. The dismissal rested on the integrand decaying to zero at its endpoint, which holds for a comparison run to the end of the record but not at the reference's own horizon, where the final entry is the divergence of a still-partial posterior from the fully informed one. At one reported time that entry is 9.3e-06, or 2.7e-04 of the peak. Following the reference's closure rule, derived rather than transcribed, moved the disagreement to 1.37e-14 and removed a latent defect at the same time: the previous panel assumed equal spacing while the exact objective range integrates a logarithmic grid, which no shipped configuration happened to trigger.

Eliminating a hypothesis by reasoning is ordinary practice and usually fine. Where the reasoning is what the conclusion rests on, the premise has to be measured on the case in hand. The accuracy given up here is real, since the replaced rule is about three times more accurate against the exact integral. Transcription fidelity on the quantity the method leads with was judged to matter more, and the trade is recorded rather than presented as a free improvement.

An empty comparison is not a passing comparison

A comparison in which no element was resolved by both sides reported success, because the maximum of an empty numeric vector is negative infinity, which sails under any threshold. An empty comparison is now a named failure, and it fired on the first run afterwards.

Verification code earns no exemption from the scepticism it exists to apply. The instrument built to catch a class of error in the package had the same disease.

Claims about coverage go stale faster than the code they describe

A previous summary stated that capability parity with the reference was complete. It was not: the reference computes the objective range two ways, as an efficient underestimate and by its definition, and only the first had been implemented. Both are now returned, and the second agrees with the reference to 1.6e-14 once the comparison horizons match.

Both review rounds found documentation asserting something that had ceased to be true, corrected on the surfaces the author had touched and left standing on the others. The suite now fails the build if a retired claim reappears in the sources, the manual, the articles or the release notes, which makes the check mechanical rather than a habit.

09

Open problems

Four questions are live, and they are the most likely places for someone else to contribute.

  • Extending grounded coverage. The influence range and the conditional construction have not been compared against the authors' code for the predator-prey system, and four of the five climate scripts are captured and passing their validity conditions but not yet gated. The instrument is built and the remaining work is per-script rather than structural. The eight unverified records were removed from the manifest rather than left in place claiming a grading they did not have.
  • Calibrating the censoring margin. How much lookahead does an influence range need before it can be called resolved? A static fraction of the remaining record is not a property of the system, and the reference's fixed 0.6 time units is a physical scale that suited one figure. The honest answer is probably that the amount of lookahead a range needs is the range itself, which makes the question circular and therefore interesting.
  • An oracle for the conditional construction. This is the one capability with no counterpart in the reference to grade against, because the reference implements it as a documented manual edit rather than as code. What a grounded oracle for it would even look like is an open question, and at present it is graded only by the package's own tests, which the manifest states plainly.
  • Generalising the instrument. Byte-verified hoisting is not specific to this method. Any published method whose reference ships as scripts rather than as a library has the same problem, and the extraction, capture and equality-gate machinery would carry over with a new manifest. Whether that generalises cleanly is untested on a second reference.

Two capabilities are queued behind those questions, in the order the evidence supports. The first is a set of adequacy diagnostics built on the innovations of the fitted filter, meaning its one-step prediction errors, which attacks the largest declared gap in the package's own assumptions article. The second is a mixture prior, which keeps the system exactly conditionally Gaussian and so splits the metric in closed form without changing the numerical core.

10

Working practices

The package has one author, so there is no multi-author governance to describe. Review has come from two structured rounds against the whole tree, each producing written findings answered in writing, with the responses kept in the repository and pinned to the commit they were written against. Where a finding was declined, the reason is recorded next to it.

The method is the authors', and the attribution travels with the code rather than only with the prose. The reference implementation's copyright holder is named as a copyright holder in the package metadata and in both licence files, the verification harness headers carry the same notice, and the quoted excerpts in the companion document carry it beside the code they quote. The package is MIT licensed, as is the reference.

Reproducibility here follows the standard Peng sets for computational science, that code and data sufficient to regenerate the published results travel with the claims. Three commitments implement it. Fixtures are hashed in a committed manifest recording the upstream repository and commit, the licence, the MATLAB release, the generating command, the parameters and the seed, and the suite checks the shipped bytes against those hashes. The companion document is generated from the manifests and the measured results, with both code panes read from source at render time, so it cannot drift from what was actually run. The reference itself is treated as re-clonable rather than vendored, and the extraction is reproducible from an upstream clone in one command.

A collaborator joining this work would find a core that is settled and graded, an interface documented with a lifecycle stage per export, and open work concentrated in the four questions above.

## where the direct form loses it: at ratio 1 + 1e-12 the direct expression
