## Status

Decided 2026-09-02 by Max Moldovan. The package is tagged `acir-v0.1.0` on
the `acir-package` branch once the release pull request merges, and
`acir-package` is promoted to `main`. The tag marks the parity milestone the
2026-08-28 decision defined: every quantity the reference MATLAB programs
compute is reproduced to the tolerance class recorded in the evidence
register, and, after the performance work of 2026-09-01 and 2026-09-02, every
stage of the specification's performance table is inside its budget on the
development machine.

Three interface decisions were taken for this release and are recorded here
because a tag makes them expensive to reverse: the model coefficient
functions keep the names `Lx`, `fx`, `Ly`, `fy`, `Sx1`, `Sx2`, `Sy1`, `Sy2`
rather than the paper's underscore notation; the entry point keeps the shape
`aci(model, obs, ...)`; the simulation horizon is renamed from `T` to `t_end`,
with the old name accepted behind a typed warning until 0.2.0. The
maintainer field is Aidan Moller, both authors are authors and copyright
holders, provisionally.

## Alternatives considered

| Option | One-line description |
|---|---|
| A (CHOSEN) | Tag now, at parity and inside every budget, with the interface as built |
| B | Tag after the batch axis and the bench redesign as well |
| C | Rename the coefficient functions to the paper's notation before the tag |
| D | Tag without the horizon rename and carry `T` into 1.0 |

## Rationale for rejection

### Option B

The plan of 2026-09-01 placed the tag after the scalar-rows step on the
budget argument, and that argument is now met with margin. The batch axis
changes no number and no interface, and the bench redesign is an
instrument; neither is a reason to hold a parity tag.

### Option C

A rename of a tested public interface immediately before a parity tag buys
churn against a co-author's test suite for no numerical gain. The paper's
notation can arrive as aliases with the formula front end at 1.0.

### Option D

`T` shadows the alias of `TRUE` in R and lints at every site. The rename is
cheap at 0.1.0, when the user base is the two authors, and would be a
breaking change at 1.0.

## Forward cost

Low for the tag itself. The horizon rename carries a deprecation path to
0.2.0, one warning class and one test file. Reopening either naming decision
before 1.0 costs a breaking change announced in `NEWS.md` under the
API-stability statement shipped with this release.

### Reviewer ranking + rationale (independent)

A. The release gate the co-author approved was the scalar-rows step, and it
is merged with the range at 0.28 to 0.30 s against 0.40 s; the benchmark
shows zero budget warnings and the tarball check is clean with 6,601 tests
and rendering vignettes. The horizon rename is cheapest now: 14 lint sites,
two users, and a stability statement that already licenses pre-1.0 breaks
with a NEWS entry; the typed deprecation keeps the old spelling working.
Keeping the coefficient names avoids churning a 6,000-expectation suite for
underscores that a planned front end can alias.

B. Neither pending item is a gate. The batch axis changes no graded number
or interface and targets a case with no budget; the benchmark redesign
fixes an advisory instrument defect. Both belong in 0.1.x; holding the tag
for them departs from the agreed plan with no correctness gain.

D. Same shipping evidence as A, but it forecloses the one moment the rename
is nearly free and commits a shadowing name into a semver-locked 1.0.

C. Highest cost, lowest gain: the rename ripples through the co-author's
suite and the development record for a notation difference of underscores
only, with aliases already planned for 1.0.

### Missing evidence the reviewer named, and the primary's answers

- Whether parity extracts or the liveness register reference `T` or the
  coefficient names by string: the register names features, not arguments;
  two fixture manifests carry the generating call with `T =` as history.
- Whether 0.1.0 is a git tag only or an outward release: a git tag and a
  GitHub release, no CRAN submission; the six advisory CI warnings and the
  unbudgeted 44 s matrix case are recorded for the bench redesign.
- CI on the merged head across runners: the push-triggered matrix on the
  merged head before the release branch was green on six platforms; the
  release pull request runs it again.
- A liveness test for the deprecation path: test-34 asserts the warning
  class, identical draws under either name, and refusal of both names.
- The co-author's explicit view on the rename: told, not asked; his review
  of the release pull request is the point at which he can object.

### Risk the reviewer raised

That a positional horizon call cannot be disambiguated: it can, because
`t_end` occupies the formal position `T` had, so positional calls are
unchanged; only a named `T` reaches `...`, where it is intercepted and
tested.

## Decision brief

acir 0.1.0 is tagged as the parity milestone: the reference implementation
reproduced to recorded tolerances, every performance budget met. The
interface ships as built, with one rename, the horizon argument, made now
while it is cheap. The batch axis and the bench redesign follow the tag.
