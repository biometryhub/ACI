01

Why this document exists

A researcher deciding whether to build on a piece of scientific software needs two different things. The first is evidence that the numbers are right, and that is the companion document. The second is visibility into how the software was made: which choices were deliberate, which alternatives were weighed and set aside, what broke along the way, and which claims the author has retracted. That is this document.

It is written for a prospective collaborator or a reviewer, not for a user of the package. A reader who wants to know what the software does should start with its vignettes. A reader who wants to know whether its development was disciplined enough to build on will find the record here, including the parts that are unflattering.

02

The problem, and what the package contributes

Assimilative causal inference asks how much the future of an observed signal tells you about the present state of something you cannot observe. For a conditional Gaussian nonlinear system the two posteriors involved are available in closed form: a forward filter that has seen the record up to now, and a backward smoother that has seen all of it. The relative entropy between them, evaluated at each instant, is the causal-information metric. A second quantity, the causal influence range, measures how far ahead one must look before that answer stops changing. The method is due to Andreou, Chen and Bollt, published in Nature Communications in 2026.

The authors publish their code, which is more than most methods papers do. What they publish is seven top-to-bottom MATLAB scripts totalling 12,339 lines, of which exactly two files are callable functions, and both of those are third-party utilities rather than the authors' own work. Running the method on a new dataset therefore means reading someone else's script and retyping its algebra. Every reader who does that produces a private, ungraded reimplementation.

This package makes the method callable, with its mathematical preconditions enforced rather than assumed, and with a stated account of what its evidence covers. It has two dependencies, graphics and stats, both shipped with R.

The harder contribution is the verification, and it generalises beyond this method. A reimplementation graded against fixtures its own author transcribed can only demonstrate self-consistency: if the author misread an equation, the fixture encodes the same misreading and passes. The package therefore ended up building an instrument that grades it against the authors' code directly, by hoisting the reference's computational passages into callable functions as byte-exact slices, never retyped. Any method whose reference implementation ships as scripts rather than as a library has the same problem and could use the same instrument.

03

Conceptual genesis

The organising principle was that the package should be small and trusted rather than large and plausible. Capability was allowed to arrive only with its grading, or with an explicit declaration that it was ungraded; a capability that could be neither graded nor declared was not allowed to ship at all. That principle is enforced mechanically rather than remembered, which is the subject of one of the decisions below.

The ordering of the first two commits records the priority. The oracle harness and its fixtures were built and committed before the package was scaffolded. The evidence came first and the software was fitted to it.

04

Design decisions as the working record

Twelve decisions are recorded in the repository, each in a fixed shape: what was decided and when, what alternatives were considered, why each was rejected, and what the decision will cost in future. The rejected alternatives are the part worth reading. A decision recorded without them is an assertion; recorded with them it is an argument a reader can disagree with.

Six of the twelve are set out below. The remainder are listed in the index at the end.

Reference kernels become callable by byte-verified hoist, and the generated files are not committed

To run the authors' algebra on data other than their own, their computational passages have to become functions. They are hoisted, never retyped: each generated function is a signature, a byte-exact slice of the reference between explicit markers, and an end. A checker re-reads the slice from source and fails on a single byte of drift, and separately refuses any executable line outside the markers.

Rejected: keeping the hand-transcribed harnesses, which are the reason the work exists; re-implementing the kernels in MATLAB from the paper, which would have looked the most professional and graded nothing, since a third implementation by the same author is a third opportunity for the same misreading; committing the generated files, defensible under the upstream licence but inconsistent with treating the reference as re-clonable; and refactoring the reference scripts in place, which destroys the thing being verified, because once the file is edited "byte-identical to the reference" has no referent.

Forward costEach further model costs a manifest record per kernel and a gate run. An upstream re-clone must be followed by the byte check, which fails loudly if line numbering has moved.

Reference workspaces are captured under a machine-verified minimal substitution

The plan had said "run the original script unmodified". That is not available: at its published settings the dyad script allocates a 20601 × 20601 matrix of 3.40 GB and three online-smoother triangles of roughly 10.8 GB. The problem size is therefore reduced by substitutions declared in a manifest, and a tool asserts before the run that the substitution is minimal: nothing is changed beyond the declared knobs.

Rejected: running unmodified and waiting, the honest ideal but not reachable on available hardware; capturing a cheap prefix with a debugger breakpoint; reducing the size without verifying minimality, which would leave the gold side of the comparison unaudited; and abandoning workspace capture entirely.

Forward costEach new script needs a knobs record with a justification and a list of conditions that must hold after substitution. The conditions earned their place on the first run, when a reduced profile turned out to have a reporting window shorter than the lookahead it was measured against.

Scripts that collide on variable names are composed section by section

The predator-prey script cannot be run top to bottom without silently producing wrong results. It carries fourteen blocks headed "run this code section to study the causal relationship", seven for each causal direction, and every block assigns the same names. The filter mean is written for direction one and overwritten by direction two before anything consumes it, so a whole-script run computes direction one's smoother from direction two's filter. Nothing raises, and the numbers look plausible. Each direction is therefore composed from its own declared line ranges, guarded by a condition that holds in one direction only.

This is not a defect in the reference when it is used as documented: its own banners tell the reader to run one section at a time. It is a hazard for anyone automating it, and the dyad's linear structure makes whole-script capture look like the general case when it is not.

Forward costEvery further script must be inspected for name collisions before a profile is declared. The five scripts of the climate case study are each around two thousand lines, and the same pattern would be easy to miss.

The online smoother reconstructs its update products in logarithms

The reference stores the fixed-lag online smoother as nested staggered arrays, one row per observation, each row holding an estimate at every earlier instant. That is quadratic in the record and cannot run at the scale of the published figure on ordinary hardware. The implementation accumulates the ordered products of the per-step factors in logarithms and truncates them once they fall below tolerance, which makes the work bounded by the effective lag and the memory linear in the signal.

The redesign is graded rather than assumed. A literal transcription of the reference triangle is kept permanently in the test suite and the fast path is checked against it, agreeing to 2.4e-15 at 400 steps. That test is slow by design and is documented as not removable for being slow.

Forward costThe reduction is one-dimensional. Matrices do not commute, so the vector implementation keeps the geometric truncation but not the logarithmic reconstruction.

The package stays pure R

Compiled kernels were adopted for the quadratic recursion and the three-million-step climate filter, and the decision was reversed the same day when two constraints landed together: the package targets CRAN first, and reproduction at published scale moves to a companion repository rather than living in the package. Both halves of the original justification left the package with that second constraint.

Forward costThe pure-R ceiling is now an accepted limit. The published influence-range figure is a batch computation rather than an interactive one, and this is documented in the function rather than guarded in code. Whatever reproduces the climate case study at full resolution inherits the performance problem.

An unresolved influence range is reported as a bound, not as missing

A time near the end of a record cannot have its influence range resolved, because the observations that would settle it do not exist. Such a time yields a small number that reads as a confident short range. The package first returned NA there. After review it returns the computed value as a right-censored lower bound, with a four-valued status field, on the reasoning that a range consuming most of the available record is not an absent measurement but a censored one. Only the case with fewer than three later observations, where no quadrature exists, still returns NA.

Rejected: keeping NA; returning the value with no flag, as the reference does; dropping the older saturated field rather than defining it in terms of the new status, which would have broken callers for tidiness.

Forward costThe margin that decides censoring defaults to 0.1, which is a judgement rather than a calibrated constant. It is documented as this package's own device, and it is the principal reason the function is marked experimental. Calibrating it across the three worked systems is open.

05

The development cycle

Thirty-five commits between 11 July and 15 August 2026. The timeline is reconstructed from the repository history rather than from recollection, so a reader with the repository can check it.

11 July · before the package

The oracle harness, then the scaffold

A MATLAB harness reproducing the deterministic core of the reference, its fixtures, and a validated dyad calculation, all committed before the package existed. The release candidate followed in the next commit.

15–16 July · 0.1.0

Contracts, and the first gap in the evidence

Inputs that previously produced missing values or low-level errors became explicit rejections naming the argument and index. A second fixture was added for the noise cross-covariance path, because every scalar model in the reference sets that covariance to zero and so exercised those terms without ever grading them. A review round then corrected a diagnostic that miscounted, split a figure whose two series shared an axis they had no business sharing, and carried the upstream copyright into the licence files.

13 August · capability

Nine commits in one day

The causal influence range, a latent self-drift that may depend on the observed state, the noisy predator-prey model in both causal directions, vector-valued states, the conditional construction, a Milstein scheme for state-dependent diffusion, the stochastic climate model, and the grading register that gates the build. Capability and its grading were never separated by more than a day.

14 August · parity

Graded against the authors' code, not against a transcription

The hoisting instrument, extended across three of the reference's systems, and with it the first grading of the influence range that did not share a convention with the thing under test. A second review round followed, and 0.2.0 closed it.

15 August · 0.2.1

Documentation

The vignettes typeset their mathematics at the size of the surrounding text, and without fetching anything from the network.

Two patterns are visible in retrospect. The first is that both review rounds produced corrections to claims the author had already made in writing, rather than only to code. The second is that the largest single advance, grading against the authors' own code, was prompted by noticing that a strong-looking agreement had been measured against a harness that shared the convention under test.

06

Testing and verification

The suite is 736 tests across 23 files with no skips, and R CMD check --as-cran reports no errors and no warnings. Those numbers describe volume rather than strength, and the interesting question is what the tests are checked against.

Three oracles, none sufficient alone

The first is the authors' own dyad reference, reproduced by a MATLAB harness at the published parameters and seed. The second is a cross-noise harness with no upstream counterpart, because no scalar model in the reference exercises a non-zero noise cross-covariance; it is a second independent implementation of the published equations, which refutes a transcription error without being an authors' grounding. The third is algebraic: for a constant-coefficient system the stationary filtered covariance is the positive root of a Riccati equation, and that fixed point depends on neither implementation. Each fixture records, in a committed manifest, both what it grades and what it does not.

A register that fails the build on an undeclared gap

A term can be publicly reachable, execute on every run, be reported as covered by line coverage, and be graded by an oracle, while still being checked against nothing, because the fixture that grades it multiplies it by zero. That is what happened to the scalar noise cross-covariance. The response was not a note to remember: the suite now holds a register that reads which components each oracle actually grades, and the build fails when a capability appears that is neither graded nor declared ungraded.

Parity against the reference

Each hoisted function is called with the inputs the script itself used, and every output must equal, not approximate, the value the script produced. That gate stands at 124 of 124 outputs across five profiles at a maximum absolute difference of exactly zero, over 1,681 verbatim reference lines in 25 extracts. Against that instrument the package's own scalar core agrees on 26 of 26 quantities on two datasets, worst case 1.5e-14. The committed dyad fixture was re-graded at the published record length and agreed with the authors' output at a difference of exactly zero, which retired a standing doubt about the transcription rather than confirming one.

No comparison returned exact equality between the two languages, which is itself the evidence that both sides genuinely execute. Two independent implementations agreeing bit for bit would mean one of them had not run.

07

Implementation patterns

Relative entropy evaluated without cancellation

The dispersion term of the Gaussian relative entropy subtracts two nearly equal quantities. Written naively it loses the value precisely where the metric is smallest: at a covariance ratio of 1 + 1e-12 it returns zero where the correct value is 2.5e-25. Writing the ratio as 1 + d and evaluating in that form keeps it. Values at the round-off floor are clamped within a documented tolerance, and anything more negative is an error rather than a result.

Dispatch on the shape of the components

Vector states were added beside the scalar implementation rather than replacing it. A matrix latent-noise covariance selects the vector path and a bare number the scalar one. At one dimension the two agree bit for bit, which is tested, but the scalar recursion is around thirty times faster and is what the oldest oracle grades; replacing it would have spent a validated asset to buy nothing.

Failing closed on the covariance

An explicit Euler scheme can drive a posterior covariance out of its domain when the step is too large for the system, even though the model itself is admissible, and the relative entropy that scores the result has no meaning in that state. The filter and smoother check at every step and stop at the first value that is not finite and strictly positive, naming the algorithm, the index, the time and the value. In the vector case positive-definiteness is checked by attempting a Cholesky factorisation rather than by a proxy for it, and the relative entropy is evaluated through Cholesky factors rather than an explicit inverse or a determinant formed as a product.

Comparison criteria that survive a zero crossing

The parity harness's first full run reported one quantity out of tolerance at a relative error of 4.2e-11. The maximum sat at the only point in a 3,001-step series with magnitude below 1e-3, against a series median of 0.864, where the absolute difference was 7.0e-15. The defect was in the criterion rather than in either implementation: a purely relative test divides by the value, so at a zero crossing it divides by nothing in particular. The criterion is now mixed, absolute plus relative, with every relative tolerance left where it was, and each comparison reports how much of its permitted budget the worst element consumed.

08

Issues that came up

Issues that came up during development are documented here, including those that reflect poorly on earlier claims.

Terms that executed on every run and were graded by nothing

Symptom. Line coverage was total and the oracle agreed to 1e-14, while the noise cross-covariance terms had never been compared with anything.

Cause. Every scalar model in the reference sets that covariance to zero. The terms ran on every fixture and were multiplied by zero, so an error in them was invisible.

Fix and verification. A second harness with correlated noise, analytic Riccati fixed points that depend on no implementation, and a build-gating register that measures which components each oracle actually exercises.

Why it matters. A high coverage figure beside a graded oracle had been manufacturing confidence in an ungraded path.

A time-varying covariance read only at its first step

Symptom. A three-dimensional observation-noise covariance that changed over the record produced a result identical, to the last bit, to a constant one.

Cause. The vector schema accepted the array and inverted only its first slice.

Fix and verification. Positive-definiteness and inversion now happen at every step. The grading register tests the general property instead of the instance: a coefficient is genuinely consumed only if perturbing it at a late step changes the answer.

Why it matters. Nothing caught it. Not the oracles, whose fixtures held that covariance constant; not the contracts, which accepted the array; not line coverage, which was total.

A residual eliminated by argument rather than by measurement

Symptom. The objective influence range differed from the reference by 4.58e-09, and the quadrature-closure explanation had been tested and dismissed.

Cause. The dismissal rested on the integrand decaying to zero at its endpoint, which holds for a comparison run to the end of the record but not at the reference's own horizon, where the final entry is the divergence of a still-partial posterior from the fully informed one. At one reported time that entry is 9.3e-06, which is 2.7e-04 of the peak. The argument was doing structural work in the conclusion and had never been measured on the case at hand.

Fix and verification. The closure now follows the reference's rule, derived rather than transcribed and asserted to reduce to the published coefficients at equal spacing. The disagreement moved from 4.58e-09 to 1.37e-14. The same change removed a latent defect: the previous panel assumed equal spacing while the exact objective range integrates a logarithmic grid, which no shipped configuration happened to trigger.

Why it matters. The accuracy that was given up is real. The replaced rule is about three times more accurate against the exact integral. Transcription fidelity on the quantity the method leads with was judged to matter more, and the trade is recorded rather than presented as a free improvement.

The verification harness passed vacuously

Symptom. A comparison in which no element was resolved by both sides reported success.

Cause. The maximum of an empty numeric vector is negative infinity, which sails under any threshold.

Fix and verification. An empty comparison is now a named failure. It fired on the first run afterwards.

Why it matters. The instrument built to catch this class of error in the package had the same disease.

A capability parity claim that was not true

Symptom. A previous session's summary stated that capability parity with the reference was complete.

Cause. The reference computes the objective range two ways, as an efficient underestimate and by its definition. Only the first had been implemented.

Fix and verification. Both are now returned, and the second agrees with the reference to 1.6e-14 once the comparison horizons match. The claim was retracted in the same document that had made it.

Why it matters. The suite now fails the build if a retired claim reappears in the sources, the manual, the vignettes or the release notes. Two review rounds each found documentation asserting something that had ceased to be true, corrected on the surfaces the author had touched and left standing on the others.

09

What is not done

Stating the boundary is part of the evidence, so it is stated here rather than left to be discovered.

  • The influence range and the conditional construction have not been compared against the authors' code for the predator-prey system. The extracts and the equality gate are complete for both directions; the package-side comparison was run for the dyad and for the climate model's core only.
  • Four of the five climate scripts are captured and pass their validity conditions, but their extracts are not yet gated. The eight unverified records were removed from the manifest rather than left in place claiming a grading they did not have.
  • The margin governing censoring of an unresolved range is a judgement, not a calibrated constant, and the function is marked experimental principally for that reason.
  • The conditional construction has no counterpart in the reference to be graded against, because the reference implements it as a documented manual edit. It is graded only by this package's own tests, and the manifest says so.

The next capability lane, in the order the evidence supports, is a set of adequacy diagnostics built on the innovations of the fitted filter, which attacks the largest declared hole in the package's own assumptions documentation, and a mixture prior, which keeps the system exactly conditionally Gaussian and so splits the metric in closed form without changing the numerical core.

10

Governance and reproducibility

The package has one author, so there is no multi-author governance to describe. Review has come from two structured review rounds against the whole tree, each of which produced written findings that were answered in writing, with the responses kept in the repository and pinned to the commit they were written against. Where a finding was declined, the reason is recorded next to it.

The method is the authors', and the attribution travels with the code rather than only with the prose. The reference implementation's copyright holder is named as a copyright holder in the package metadata and in both licence files, the verification harness headers carry the same notice, and the quoted excerpts in the companion document carry it beside the code they quote. The package is MIT licensed, as is the reference.

Reproducibility rests on three commitments. Fixtures are hashed in a committed manifest that records the upstream repository and commit, the licence, the MATLAB release, the generating command, the parameters and the seed, and the suite checks the shipped bytes against those hashes. The verification document is generated from the manifests and the measured results, with both code panes read from source at render time, so it cannot drift from what was actually run. The reference itself is treated as re-clonable rather than vendored, and the extraction is reproducible from an upstream clone in one command.

A collaborator joining this work would be taking on a package whose core is settled and graded, whose interface is documented with a lifecycle stage per export, and whose open work is concentrated in two places: completing the parity coverage for the systems listed above, and the calibration of the one defaulted constant that currently rests on judgement.

Appendix A · patterns in code

The dispersion term, written to survive cancellation

## ratio = R_s / R_f. Writing it as 1 + d and expanding keeps the value
## where the naive form loses it: at ratio 1 + 1e-12 the naive expression
## returns 0, where the correct value is 2.5e-25.
d <- (R_s - R_f) / R_f
dispersion <- 0.5 * (d - log1p(d))

Dispatch on the shape of the components, not on a flag

  if (.aci_is_mv(comp)) {
    ## matrix latent-noise covariance: the vector path
    return(.aci_filter_mv(x, comp, dt, mu0, R0))
  }
  ## bare number: the original scalar recursion, untouched and ~30x faster
  .aci_check_signal(x)
  ...
}
