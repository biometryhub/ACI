# FBCIR multiscale oracle status

The supplied `FBCIR_code-main` archive contains MATLAB source but no numerical
output files (`.mat`, `.csv`, or figure data). Therefore no existing asset can
honestly be called an author-provided numerical fixture.

`generate_fbcir_multiscale_oracles.m` executes hash-verified temporary copies
of the three supplied multiscale scripts. It only shortens the run, starts the
reporting window at zero, hides figures, disables optional heatmap caches, and
retains online histories for export. Generated files are **authors-source
execution fixtures**, not author-provided outputs and not a fresh transcription
of the CGNS equations.

The pinned source SHA-256 values are:

- joint: `06685f0d46868bac65a47ff161a7b8c9933a2b0f1fb1a0f53132bd97e6b51827`
- conditional y1: `cf10812535b84e513d9dd75dc68f601915de10beb5326de42f2e1e88b1ae4054`
- conditional y2: `49f067005226bf21d61cb9c5f7d358c3a1cdead70c84ec93d637d38f068d7f43`

The joint route exercises correlated, matrix-valued (`k = 2`, `l = 2`)
filter, smoother, ACI, fixed-lag online, adaptive-lag online, and CIR code. The
marginal routes exercise the authors' conditional likelihood mask with observed
ordering `(x1,x2,y2)` for latent `y1`, and `(x1,x2,y1)` for latent `y2`.

Authors-source numerical parity remains an open evidence item: generated bytes
must be hash-pinned, the actual MATLAB release recorded, and always-on package
tests added for all three routes. The package's retired R kernels did not carry
these missing outputs and therefore could not close this evidence gap. Future
tests must call `nontarget(..., strategy = "inflate")` on the marginal models:
the source masks the already-inverted observation precision. Calling a marginal
constructor without that mask is a different, unconditional Bayesian update.
