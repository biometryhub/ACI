# Summary

`acir` is one R package that computes assimilative causal inference
(ACI) for conditional Gaussian nonlinear systems exactly as the method’s
authors define it: every quantity they compute in closed form, checked
number by number against their published MATLAB programs, in base R with
no dependencies beyond `stats` and `graphics`, and built so that later
methods are callers of the engine rather than rewrites of it.

It is the hybrid of `aciR` 0.2.3 (Max Moldovan) and `aci` 0.0.30 (Aidan
Moller). Version 1.0 of this specification was written before either of
us knew that a working merge of the two packages had already been
completed on the `aci` side, blind to the specification. The technical
review of v1.0 reports that the merge matches the scope rule, name,
licence and numerical policies almost exactly, that it passes every
`ACI_code` fixture (the v1.0 milestone `acir-v0.1.0`), and that it adds
eight findings the specification lacked. This version consolidates the
two: the specification is now stated against the engine as built, every
review item is recorded as applied, revised or left for decision, and
the build plan is restated as the audit of that engine plus the staged
work that remains. The merged engine has not yet been run on this side
(it is not on a shared branch), so its reported state is carried as
reported until it is.

## The scope rule

Everything the authors compute in closed form inside the conditional
Gaussian class belongs in the engine. Everything they compute by
ensemble or by learning is a caller, behind a socket whose contract the
engine fixes. Outside the linear-Gaussian and conditionally Gaussian
classes there is no finite-dimensional exact filter, so “approximate the
model and solve exactly” is the engine’s business and “keep the model
and solve approximately” is the backend’s; the two meet on overlap
models, where the engine is the backend’s oracle.

`S_xoS_x`, `S_yoS_y`, `S_yoS_x`), so a reader can diff the R against the

the rename is in progress.

# Model contract

A conditional Gaussian nonlinear system with observed block `x` (k
variables) and hidden block `y` (l variables):

$$\mathrm{d}x = \big(f_x(t, x) + L_x(t, x)\, y\big)\,\mathrm{d}t + \Sigma_x(t, x)\,\mathrm{d}W_1,
\qquad
\mathrm{d}y = \big(f_y(t, x) + L_y(t, x)\, y\big)\,\mathrm{d}t + \Sigma_y(t, x)\,\mathrm{d}W_2,$$

with optional correlated noise through `S_yoS_x`. Coefficients are
accepted as functions of the observed row, as arrays on the grid, or by
name from the library; at 1.1, as a formula. All compile once to arrays
on the grid, the precision path of the observation Gram matrix, flags,
and a fingerprint. Validation before any arithmetic: shape agreement,
linearity in `y`, positive semi-definite joint noise covariance,
consistent grid. Failure raises a typed condition naming the check.

**Compatibility switches, all off by default.** The engine’s defaults
are the consistent model; each switch reproduces one recorded behaviour
of a reference script so that its outputs can be matched exactly.

| Switch | Reproduces | Measured effect of the reference behaviour |
|----|----|----|
| `phase = "shifted"` | the climate-model script’s coefficient phase (coefficient at index j applied one step off the consistent convention) | filter mean about 1e-3, ACI about 2.6e-2 on the T_C case; the review measured and documented the delta rather than building the switch, and is open to building it; this version asks for it, since script-exact replay is the package’s claim |
| `first_step = "matlab"` in `aci_conditional()` | the conditional scripts’ unmasked first mask slice (the full pseudo-inverse fills slice one before the target-only overwrite) | filter mean moves 0.108 at step 2; integrated ACI 1.4 percent |
| `literal = TRUE` | two source defects in the ENSO scripts (section *Evidence*, findings 1 and 2) | up to a doubling of time-integrated ACI on a 14-model-year window (finding 2); covariances unaffected |

The state-time convention (the coefficient at index j belongs to the
state at t_j) is the default. `blocks` declares block structure for
block-wise recursions.

# Architecture

Five layers (interface; one-time evaluation; engine; results; evidence)
and seven code blocks (model compiler; recursion driver; step kernels;
Gaussian information; range; conditional; results and evidence), as in
v1.0. Target size about 6,000 lines of R excluding tests.

**Measured design decisions** (base R 4.5.2, medians of five; scripts
and outputs under `comparison/core_engine/strategy/`):

| Question | Measurement | Decision |
|----|----|----|
| batch axis for the scalar kernel | 3,000 steps: 1 record 6 ms, 10 8 ms, 100 29 ms, 1,000 164 ms; bit-identical to separate runs | adopt, as its own gated change after the audit (the review’s staging: large blast radius into a verified engine) |
| batch axis for a matrix hidden state | l = 2: 100 records cost 2.9 times one; l = 6: 7.7 times | arrays for P \> 1, the dense path for P = 1, both graded identical |
| a step-closure driver | 0.70 microseconds per step inline, 1.07 through a closure | code template for scalar kernels, runtime driver for matrix kernels |

Two levers designed and gated, not measured: the influence range formed
for a block of reporting times with the lag as the loop; the
constant-coefficient shortcut. The compiled inner loop stays out.

# Numerical policies

- **Closed forms only.** As in v1.0, with one revision: the exact
  objective range has a closed form (the running-maximum sum over lags),
  which the engine implements as `method = "exact"`; the reference’s
  Simpson quadrature over the threshold grid (513 nodes by default) is
  `method = "reference"`, and the paper’s efficient formula is
  `method = "approximation"`. The exact value and the reference
  quadrature differ by about 5e-4 on the objective-bridge comparison, a
  discretisation gap, recorded.
- **Covariance policy, revised.** The default is strict: a covariance
  that fails the positive-definiteness check stops with `aci_error_spd`
  naming the step. An eigenvalue floor is opt-in, explicit and counted.
  The reference’s regulariser (`FBCIR_code/shared_helper.m`: real
  projection, symmetrisation, floor at `eps(max(1, max |lambda|))`,
  spectral reconstruction) is provided as the compatibility regulariser
  for the `FBCIR_code` family and its fixtures. Basis: the review
  measured zero floor activations in 4.37 million covariance updates
  across every published case, and one stress case in which an always-on
  floor silently replaced a variance of -1.07e13 with 1e-12 and
  completed. `ACI_code` has no regulariser.
- **Tolerances.** `|a - b| <= atol + rtol |b|`, both 1e-12 for linear
  quantities and 1e-11 for logarithmic ones; bit-identical matches
  recorded as such. Adaptive truncation in the online smoother
  (`tol = 1e-8`, the documented default) is switched off (`tol = 0`)
  when comparing against stored outputs; at `tol = 0` the streaming and
  table range routes agree at machine precision (maximum 4.7e-16;
  subjective read-outs bit-identical), which closes the 2.2e-7 item of
  v1.0 as a documented default, not a defect.
- **Randomness.** Seed argument, caller’s random state restored, drawn
  increments returned; increments accepted as input from the sampling
  stage onwards. A MATLAB seed does not reproduce an R draw, so
  fixed-increment fixtures ship the increments.
- **Parallelism.** Outer loops only, one L’Ecuyer stream per unit,
  arriving with the batch-axis change.

# Evidence

**Register.** One row per feature, shipped as
`inst/evidence/register.csv`, rendered in the validation vignette, and
enforced by a build-failing coverage test (adopted by the review).
**Gate liveness**: every gate shown to fail once on an induced
violation, recorded (adopted).

**Stored outputs.** `ACI_code` present; `FBCIR_code` and the `EnKBS`
sampler generated locally through the harness with the toolbox-shim
route (adopted by the review as the right unblock): the Statistics,
Econometrics and Signal Processing calls in five scripts sit in plotting
and diagnostic blocks feeding no assimilation quantity, so plain-MATLAB
shims for `ksdensity`, `normpdf`, `skewness`, `autocorr` and `xcorr` let
every script run whole on base MATLAB; the harness records which shims
were active, and no shimmed value enters a fixture.

**Reference-source findings and the source-defect policy.** The review
found, and the engine records, five properties of the reference scripts
that a literal reproduction would inherit. Policy: each is a register
row; the engine’s default is the consistent behaviour; the literal
behaviour is reproducible under the switches of section
*Model contract*; the harness’s
run-the-scripts stage treats finding 1 as a known source defect rather
than a harness failure. Whether and how the authors are told is a
separate decision (section
*Decisions*).

| \# | Finding | Engine behaviour |
|----|----|----|
| 1 | `ENSO_model_cond_ACI_tau_unobs.m` references `f_y_s` (lines 1455, 1484) without defining it; the script errors standalone; the intended value is 0 | default 0; `literal = TRUE` reproduces the reference’s intent under the compatibility flag; the harness records the defect |
| 2 | `ENSO_model_cond_ACI_T_C_unobs.m` omits `gamma_C * h_W` from the assimilation `f_y` (lines 1053, 1151) while its own simulator includes it (line 1124) | default consistent model; `literal = TRUE` reproduces the script (+102 percent time-integrated ACI on a 14-model-year window; covariances bit-identical) |
| 3 | the conditional scripts leave the first mask slice unmasked | `first_step = "matlab"` |
| 4 | the 173-row fixture set omitted the scalar ENSO partitions and the T_C zeroth-order case | both implemented and graded in the engine with source-derived fixtures; T_C as a distinct k = 2 model with simulator and inference parameterisations held separately |
| 5 | the tau script’s reduced observation set is a different quantity from the full set (time-resolved ACI differs by up to 0.78 against a mean level of 0.25; the time average agrees within 0.5 percent) | both named in the engine, reduced as the script default; the register’s ENSO row splits accordingly |

**Second implementations.** `aciR` 0.2.3 and `aci` 0.0.30 are compared
with `acir` on every shared quantity in continuous integration,
installed from the tag that marks their last state (section
*Versioning, tags and the repository*). The review
reports that everywhere the two parents’ contracts match they agree at
machine precision, so component selection in the merge was by measured
efficiency and interface.

**Audit of the engine as built.** Before the staged work resumes, the
merged engine is run on this side: the suite (reported 6,236 tests, 0
failures), `R CMD check` with the three vignettes, the register coverage
test, the gate-liveness record, and the full harness against the
`ACI_code` fixtures at the tolerances above. The reported state is
carried as reported until then.

# Performance, revised

Timings are tracked, not gated. Continuous integration records the
stages of v1.0’s table on every run and warns on a regression beyond 25
percent against the recorded baseline; no acceptance threshold fails the
build until the range and the 20,001-step rows have been measured on the
exact workloads the budgets name. The filter and smoother rows are
reported well inside the v1.0 budgets.

# Versioning, tags and the repository

**A constraint v1.0 missed.** `acir/` and `aciR/` collide as paths on
case-insensitive filesystems (macOS, Windows): a tree holding both
cannot be checked out there. The side-by-side layout of v1.0 is
therefore not available.

**Route, proposed by the review, pending sign-off.** A branch on
`biometryhub/ACI` adds `acir/` and removes `aci/` and `aciR/`, keeping
the root-level documentation, merged by pull request after review. The
last both-parents state is tagged before the removal commit, so the old
trees stay one checkout away and the full history remains; the second-
implementation comparisons install the parents from that tag. The root
README explains that `acir` is the hybrid of the two and names the tag.

**Alternative, if the parents should stay visible in the working tree.**
Move them to `parents/aciR` and `parents/aci` (no collision), at the
cost of a three-package tree and continuous-integration matrix.

**Versions and tags.** `Version: 0.0.0.9000` while developing;
package-prefixed parity tags `acir-v0.1.0` (every `ACI_code` fixture
through `acir`, which the review reports as the existing build),
`acir-v0.2.0` (the `FBCIR_code` and sampler fixtures pass),
`acir-v1.0.0` for CRAN. The project site follows `acir` from its first
tag.

# Decisions

1.  Default `method` of `aci_range()`: `"approximation"` (the
    reference’s primary output, this version’s recommendation), or
    `"exact"` (the engine’s current default, the closed form the
    reference does not compute).
2.  Repository route: tagged removal of the parents (recommended), or
    `parents/` in the working tree.
3.  Build the `phase = "shifted"` switch (recommended) or keep the
    documented delta.
4.  Whether the two ENSO source findings (1 and 2) are communicated to
    the authors, and by whom.
5.  Maintainer name at submission.
