01

Why this document exists

Two documents accompany this package. The companion answers whether the numbers are right. The present document answers how the software came to be -- which choices were deliberate, what we weighed and set aside, what the defects turned out to teach, and which questions remain open.

It is written for a reader deciding whether to build on the package or to work on it, rather than for a reader using it. Anyone who wants to know what the software does should start with its articles. Anyone who works on scientific software of any kind may find the middle sections useful on their own terms. The verification problem we ran into is general, and the vocabulary for it is older and better developed than this package.

02

The method, and why it needed reimplementing

Assimilative causal inference asks how much the future of an observed signal tells us about the present state of something we cannot observe. It applies to conditional Gaussian nonlinear systems, a class in which the statistics of the unobserved component, conditional on the observed path, remain Gaussian. In that class the two posteriors involved are available in closed form. Firstly, a forward filter has seen the record up to now. Secondly, a backward smoother has seen all of it. The relative entropy between them, i.e. the Kullback-Leibler divergence, evaluated at each instant, is the causal-information metric. A second quantity, the causal influence range, measures how far ahead one must look before that answer stops changing. The method is due to Andreou, Chen and Bollt, published in 2026.

It should be noted that the authors publish their code, which is more than most methods papers do. What they publish is seven top-to-bottom MATLAB scripts totalling 12,339 lines, of which three files are callable functions. Two are third-party utilities and the third is a console progress indicator, so none of them carries any of the method. Running it on a new dataset therefore means reading someone else's script and retyping its algebra. Every reader who does that produces a private, unchecked reimplementation.

The presented package makes the method callable, with its mathematical preconditions enforced rather than assumed, and with a stated account of what its evidence covers. It has two dependencies, graphics and stats, both shipped with R.

03

Conceptual genesis – a program with no oracle

A test oracle is the source that decides whether an output is correct. Obtaining one is known as the oracle problem, surveyed by Barr and colleagues. Ordinary software usually has a test oracle close at hand, because someone knows what the answer should be. A program written to compute something not otherwise known does not. Weyuker named these non-testable programs. It is well recognised that much scientific software belongs to the class, since such a program exists precisely because the answer is unavailable by other means.

Two established strategies address this. Firstly, a pseudo-oracle is an independent implementation of the same specification, used in place of a test oracle, proposed by Davis and Weyuker. Secondly, a metamorphic relation is a property the output must satisfy that can be checked without knowing the correct answer, surveyed by Segura and colleagues. We use both.

The pseudo-oracle carries a caveat that shaped this package. Knight and Leveson tested the assumption that independently written versions of a program fail independently, and found that it does not hold. Common failures occurred far more often than independence predicts, because different people make the same mistakes on the same hard parts. If that holds for versions written by different people, then two versions written by the same person offer no independence at all. A reimplementation checked against fixtures its own author transcribed can demonstrate self-consistency and nothing more. If the author misread an equation, the fixture encodes the same misreading and passes.

That observation is the origin of our organising rule, and of a word we use throughout. A test oracle is grounded when its expected values come from a source that did not also produce the code under test. It is not a term of art. We use it because the distinction it names is the one that kept mattering.

One further distinction sets the scope. Oberkampf and Roy separate verification, which asks whether the equations are being solved correctly, from validation, which asks whether they are the right equations for the phenomenon. The presented package is a verification exercise throughout. Whether assimilative causal inference is the right way to ask a causal question of a physical system is the method's own claim, argued in the paper that introduced it.

The approach we took is by no means new. It traces back to Davis and Weyuker's pseudo-oracle, and the increment we add is a bounded one. We make the pseudo-oracle the authors' own code rather than a transcription of it, by hoisting their computational passages into callable functions as byte-exact slices.

Two consequences followed for how we built the package. Firstly, a capability was allowed to arrive only with its grading, or with an explicit declaration that it was ungraded, and the test suite enforces that rule rather than leaving it to be remembered. Secondly, the ordering of the first two commits records the same priority, in that we built and committed the oracle harness and its fixtures before scaffolding the package.

04

Design decisions, and the alternatives we set aside

Twelve decisions are recorded in the repository, each in a fixed shape. We state what was decided and when, which alternatives we considered, why we rejected each, and what the decision will cost in future. The rejected alternatives are the part worth reading, since several of them are reasonable and a different project would choose differently. Six are set out below. The rest are in the index at the end.

Reference kernels become callable by byte-verified hoist, and we do not commit the generated files

To run the authors' algebra on data other than their own, their computational passages have to become functions. We hoist them rather than retyping them. Each generated function is a signature, a byte-exact slice of the reference between explicit markers, and an end. A checker re-reads the slice from source and fails on a single byte of drift, and separately refuses any executable line outside the markers.

Set aside:
  1. Keeping the hand-transcribed harnesses, which are the reason the work exists.
  2. Re-implementing the kernels in MATLAB from the paper, which would have looked the most professional while grading nothing. A third implementation by the same author is a third opportunity for the same misreading.
  3. Committing the generated files, permitted by the upstream licence but inconsistent with treating the reference as re-clonable.
  4. Refactoring the reference scripts in place, which destroys the thing being verified. Once the file is edited, "byte-identical to the reference" has no referent.

Forward costEach further model costs a manifest record per kernel and a gate run. An upstream re-clone must be followed by the byte check, which fails loudly if line numbering has moved.

Reference workspaces are captured under a machine-verified minimal substitution

Our plan had said "run the original script unmodified". That is not available. At its published settings the dyad script allocates a 20601 × 20601 matrix of 3.40 GB and three online-smoother triangles of roughly 10.8 GB. We therefore reduce the problem size by substitutions declared in a manifest, and a tool asserts before the run that the substitution is minimal, i.e. that nothing is changed beyond the declared knobs.

Set aside:
  1. Running unmodified and waiting, the honest ideal but not reachable on available hardware.
  2. Capturing a cheap prefix with a debugger breakpoint.
  3. Reducing the size without verifying minimality, which would leave the trusted side of the comparison unaudited.
  4. Abandoning workspace capture entirely.

Forward costEach new script needs a knobs record with a justification and a list of conditions that must hold after substitution. Those conditions earned their place on the first run, when a reduced profile turned out to have a reporting window shorter than the lookahead it was measured against.

Scripts that collide on variable names are composed section by section

The predator-prey script cannot be run top to bottom without silently producing wrong results. It carries fourteen blocks headed "run this code section to study the causal relationship", seven for each causal direction, and every block assigns the same names. The filter mean is written for direction one and overwritten by direction two before anything consumes it. A whole-script run therefore computes direction one's smoother from direction two's filter. Nothing raises, and the numbers look plausible. We compose each direction from its own declared line ranges, guarded by a condition that holds in one direction only.

This is not a defect in the reference when it is used as documented, since its own banners tell the reader to run one section at a time. It is a hazard for anyone automating it, and the dyad's linear structure makes whole-script capture look like the general case when it is not.

Forward costEvery further script must be inspected for name collisions before a profile is declared. The five scripts of the climate case study are each around two thousand lines, and the same pattern would be easy to miss.

The online smoother reconstructs its update products in logarithms

The reference stores the fixed-lag online smoother as nested staggered arrays, one row per observation, each row holding an estimate at every earlier instant. That is quadratic in the record and cannot run at the scale of the published figure on ordinary hardware. We accumulate the ordered products of the per-step factors in logarithms and truncate them once they fall below tolerance, which bounds the work by the effective lag and keeps the memory linear in the signal.

The redesign is graded rather than assumed. A literal transcription of the reference triangle is kept permanently in the test suite and the fast path is checked against it, agreeing to 2.4e-15 at 400 steps. That test is slow by design, and it is documented as not removable for being slow.

Forward costThe reduction is one-dimensional. Matrices do not commute, so the vector implementation keeps the geometric truncation but not the logarithmic reconstruction.

The package stays pure R

We adopted compiled kernels for the quadratic recursion and the three-million-step climate filter, then reversed that decision the same day when two constraints landed together. The package targets CRAN first, and reproduction at published scale moves to a companion repository rather than living in the package. Both halves of the original justification left the package with that second constraint.

Forward costThe pure-R ceiling is now an accepted limit. The published influence-range figure is a batch computation rather than an interactive one, documented in the function rather than guarded in code. Whatever reproduces the climate case study at full resolution inherits the performance problem.

An unresolved influence range is reported as a bound, not as missing

A time near the end of a record cannot have its influence range resolved, because the observations that would settle it do not exist. Such a time yields a small number that reads as a confident short range. We first returned NA there. We now return the computed value as a right-censored lower bound, borrowing the term from survival analysis, where a censored observation is one known only to exceed some value. The caveat is carried in a four-valued status field. Our reasoning is that a range consuming most of the available record is not an absent measurement but a censored one. Only the case with fewer than three later observations, where no quadrature exists, still returns NA.

Set aside:
  1. Keeping NA.
  2. Returning the value with no flag, as the reference does.
  3. Dropping the older saturated field rather than defining it in terms of the new status, which would have broken callers for tidiness.

Forward costThe margin that decides censoring defaults to 0.1, a judgement rather than a calibrated constant. It is documented as this package's own device, and it is the principal reason we mark the function experimental. Calibrating it is one of the open problems below.

The development cycle

Thirty-five commits between 11 July and 15 August 2026. We reconstruct the timeline from the repository history rather than from recollection, so a reader with the repository can check it.

11 July · before the package

The oracle harness, then the scaffold

A MATLAB harness reproducing the deterministic core of the reference, its fixtures, and a validated dyad calculation, all committed before the package existed. The release candidate followed in the next commit.

15–16 July · 0.1.0

Contracts, and the first gap in the evidence

Inputs that previously produced missing values or low-level errors became explicit rejections naming the argument and index. We added a second fixture for the noise cross-covariance path, because every scalar model in the reference sets that covariance to zero and so exercised those terms without ever grading them. A review round then corrected a diagnostic that miscounted, split a figure whose two series shared an axis they had no business sharing, and carried the upstream copyright into the licence files.

13 August · capability

Nine commits in one day

The causal influence range, a latent self-drift that may depend on the observed state, the noisy predator-prey model in both causal directions, vector-valued states, the conditional construction, a Milstein scheme for diffusion that varies with the state it integrates, the stochastic climate model, and the register that gates the build. Capability and its grading were never separated by more than a day.

14 August · parity

Graded against the authors' code, not against a transcription

The hoisting instrument, extended across three of the reference's systems, and with it our first grading of the influence range that did not share a convention with the thing under test. A second review round followed, and 0.2.0 closed it.

15 August · 0.2.1

Documentation

The articles typeset their mathematics at the size of the surrounding text, and without fetching anything from the network.

16 August · 0.2.2

The last ungraded component, and two corrections

The integrator was graded by recovering the reference's own Wiener increments from its captured path and driving the simulator with them. Predator-prey was graded end to end in both directions, and the four scalar-latent climate scripts were extracted and gated. Two of our own published claims were found wrong and corrected, one of them for the third time.

Two patterns are visible in retrospect. Firstly, both review rounds produced corrections to claims we had already made in writing, rather than only to code, which is what led to the claim-checking test described below. Secondly, the largest single advance, grading against the authors' own code, came from noticing that a strong-looking agreement had been measured against a harness sharing the convention under test.

06

How the package is graded

The suite is 777 tests across 24 files with no skips, and R CMD check --as-cran reports no errors and no warnings. Those counts say nothing about what the tests are checked against, which is the subject of the rest of this section, in the vocabulary of section three.

Three oracles, of three different kinds

Firstly, we use a grounded test oracle, namely the authors' own dyad calculation at their published parameters and seed.

Secondly, we use a pseudo-oracle in Davis and Weyuker's sense, a harness with correlated noise switched on. It has no upstream counterpart, because no scalar model in the reference exercises a non-zero noise cross-covariance, so it is a second independent implementation of the published equations in a different language and runtime. We deliberately do not describe it as grounded. The same person wrote both sides, which is the situation Knight and Leveson's result warns about. What it establishes is narrower and still worth having, namely that a transcription slip on the R side would have shown up across a full transient.

Finally, we use metamorphic relations, which depend on no implementation at all. For a constant-coefficient system the stationary filtered covariance is the positive root of an algebraic Riccati equation, a standard object in linear filtering. Started at that root, the recursion must stay there. Two further identities are checked in the same spirit. The smoother equals the filter at the final step by construction, and with no coupling the metric must vanish. These relations are grounded in the strongest sense available, since they follow from the governing equations rather than from anyone's code. Each fixture records, in a committed manifest, both what it grades and what it does not.

A register that fails the build on an undeclared gap

A term can be publicly reachable, execute on every run, be reported as covered by line coverage, and be graded by a test oracle, while still being checked against nothing, because the fixture that grades it multiplies it by zero. Our response was not a note to remember. The suite holds a register that reads which components each test oracle actually exercises, and the build fails when a capability appears that is neither graded nor declared ungraded.

Parity against the reference itself

Each hoisted function is called with the inputs the script itself used, and every output must equal, not approximate, the value the script produced. That gate stands at 156 of 156 outputs across nine profiles at a maximum absolute difference of exactly zero, over 2,159 verbatim reference lines in 33 extracts. Against that instrument the package's scalar core agrees on 26 of 26 quantities across two datasets, worst case 1.5e-14. We re-graded the committed dyad fixture at the published record length, and it agreed with the authors' output at a difference of exactly zero, which retired a standing doubt about the transcription rather than confirming one.

For scale, Hatton's T2 experiment measured independently developed implementations of the same algorithms, run on the same input data with the same parameters, and found agreement "gradually degenerated from 6 significant figures to 1 significant figure during the computation". Against that baseline, agreement at 1e-14 between an R implementation and the authors' MATLAB is not a routine outcome. It should also be noted that no comparison here returned exact equality between the two languages, which is itself the evidence that both sides genuinely execute. Two independent implementations agreeing bit for bit would mean one of them had not run.

07

Implementation patterns

Relative entropy evaluated without cancellation

The dispersion term of the Gaussian relative entropy subtracts two nearly equal quantities. Written directly, it loses the value precisely where the metric is smallest. At a covariance ratio of 1 + 1e-12 it returns zero, where the correct value is 2.5e-25. Writing the ratio as 1 + d and expanding in that form keeps it. Values at the round-off floor are clamped within a documented tolerance, and anything more negative is an error rather than a result.

Dispatch on the shape of the components

We added vector states beside the scalar implementation rather than replacing it. A matrix latent-noise covariance selects the vector path and a bare number the scalar one. At one dimension the two agree bit for bit, which is tested. The scalar recursion is around thirty times faster and is what the oldest test oracle grades, so replacing it would have spent a validated asset to buy nothing.

Failing closed on the covariance

An explicit Euler scheme can drive a posterior covariance out of its domain when the step is too large for the system, even though the model itself is admissible, and the relative entropy that scores the result has no meaning in that state. The filter and smoother check at every step and stop at the first value that is not finite and strictly positive, naming the algorithm, the index, the time and the value. In the vector case, we check positive-definiteness by attempting a Cholesky factorisation rather than by a proxy for it, and we evaluate the relative entropy through Cholesky factors rather than an explicit inverse or a determinant formed as a product.

Comparison criteria that survive a zero crossing

The parity harness's first full run reported one quantity out of tolerance at a relative error of 4.2e-11. The maximum sat at the only point in a 3,001-step series with magnitude below 1e-3, against a series median of 0.864, where the absolute difference was 7.0e-15. The problem was in the criterion rather than in either implementation. A purely relative test divides by the value, so at a zero crossing it divides by nothing in particular. The criterion is now mixed, absolute plus relative, with every relative tolerance left where it was, and each comparison reports how much of its permitted budget the worst element consumed.

08

What the failures taught

Five defects are worth recording, because each one produced a piece of knowledge that changed how we check the package. We state them lesson-first, since the lesson is the part that transfers.

Coverage and a test oracle can both be satisfied by a path checked against nothing

Line coverage was total, and the test oracle agreed to 1e-14, while the noise cross-covariance terms had never been compared with anything. Every scalar model in the reference sets that covariance to zero, so the terms ran on every fixture and were multiplied by zero. Our remedy was the second harness, the metamorphic relations, and the build-gating register.

A test oracle's scope is a claim in its own right, and needs measuring rather than asserting. A high coverage figure sitting beside a graded test oracle can manufacture confidence in an ungraded path.

Accepting an input's shape is not the same as consuming it

A three-dimensional observation-noise covariance that changed over the record produced a result identical, to the last bit, to a constant one. The schema accepted the array and inverted only its first slice. Nothing caught it. Not the test oracles, whose fixtures held that covariance constant, not the contracts, which accepted the array, and not line coverage, which was total.

The general property is cheap to test and the instance is not. A coefficient is genuinely consumed only if perturbing it at a late step changes the answer. The register now tests that, rather than testing the one case we found.

An argument is not a measurement

The objective influence range differed from the reference by 4.58e-09, and we had considered the quadrature-closure explanation and dismissed it. Our dismissal rested on the integrand decaying to zero at its endpoint, which holds for a comparison run to the end of the record but not at the reference's own horizon. There, the final entry is the divergence of a still-partial posterior from the fully informed one. At one reported time that entry is 9.3e-06, or 2.7e-04 of the peak. Following the reference's closure rule, derived rather than transcribed, moved the disagreement to 1.37e-14. The same change removed a latent defect, since the previous panel assumed equal spacing while the exact objective range integrates a logarithmic grid, which no shipped configuration happened to trigger.

Eliminating a hypothesis by reasoning is ordinary practice and usually fine. Where the reasoning is what the conclusion rests on, the premise has to be measured on the case in hand. The accuracy we gave up here is not negligible, since the replaced rule is about three times more accurate against the exact integral. We judged transcription fidelity on the quantity the method leads with to matter more, and we record the trade rather than presenting it as a free improvement.

An empty comparison is not a passing comparison

A comparison in which no element was resolved by both sides reported success, because the maximum of an empty numeric vector is negative infinity, which sails under any threshold. An empty comparison is now a named failure, and it fired on the first run afterwards.

Verification code earns no exemption from the scepticism it exists to apply. The instrument we built to catch a class of error in the package had the same disease.

Claims about coverage go stale faster than the code they describe

One of our earlier summaries stated that capability parity with the reference was complete. It was not. The reference computes the objective range two ways, as an efficient underestimate and by its definition, and we had implemented only the first. Both are now returned, and the second agrees with the reference to 1.6e-14 once the comparison horizons match.

Both review rounds found documentation asserting something that had ceased to be true, corrected on the surfaces we had touched and left standing on the others. The suite now fails the build if a retired claim reappears in the sources, the manual, the articles or the release notes, which makes the check mechanical rather than a habit.

09

Open problems

Four questions are live, and they are the most likely places for someone else to contribute.

  • Extending grounded coverage. The predator-prey system is now graded end to end in both causal directions, filter through causal influence range, at a worst absolute difference of 1.5e-12 across the twenty-six graded quantities. Two further rows report aciR's own default horizon against the reference's, which is a designed difference rather than a disagreement, and they are excluded from that figure. All four scalar-latent climate scripts are now extracted and gated at a difference of zero. What remains is the aciR side of those four, which is held up by the export rather than by the package. The harness builds its comparison bundles in a square configuration with feedback-matrix noise, and these configurations are three observed against one latent with scalar latent noise.
  • Calibrating the censoring margin. How much lookahead does an influence range need before it can be called resolved? A static fraction of the remaining record is not a property of the system, and the reference's fixed 0.6 time units is a physical scale that suited one figure. In our opinion the amount of lookahead a range needs is the range itself, which makes the question circular and therefore interesting.
  • Grading the conditional construction. We had recorded that the reference implements this by hand rather than in code, so that no counterpart existed to grade against. That was wrong, and finding it out took three attempts. Read from the source, the answer depends on spotting a comment marker, and we misread it twice. Measured instead from the observation-noise inverse each script's filter actually consumed, three of the five climate scripts ship with the conditional path live. A counterpart therefore exists. One convention has to be matched before it can be used: the reference leaves the first filter step of a conditional run unmasked, which moves the filtered mean by 0.238 at step two, and aciR masks every step.
  • Generalising the instrument. Byte-verified hoisting is not specific to this method. Any published method whose reference ships as scripts rather than as a library has the same problem, and the extraction, capture and equality-gate machinery would carry over with a new manifest. Whether it generalises cleanly is untested on a second reference.

Two capabilities are queued behind those questions, in the order the evidence supports. Firstly, a set of adequacy diagnostics built on the innovations of the fitted filter, i.e. its one-step prediction errors, which attacks the largest declared gap in the package's own assumptions article. Secondly, a mixture prior, which keeps the system exactly conditionally Gaussian and so splits the metric in closed form without changing the numerical core.

10

Working practices

The package has one author, so there is no multi-author governance to describe. Review has come from two structured rounds against the whole tree, each producing written findings answered in writing, with the responses kept in the repository and pinned to the commit they were written against. Where we declined a finding, the reason is recorded next to it.

The method is the authors', and the attribution travels with the code rather than only with the prose. The reference implementation's copyright holder is named as a copyright holder in the package metadata and in both licence files, the verification harness headers carry the same notice, and the quoted excerpts in the companion document carry it beside the code they quote. The package is MIT licensed, as is the reference.

Reproducibility here follows the standard Peng sets for computational science, that code and data sufficient to regenerate the published results travel with the claims. Three commitments implement it. Firstly, fixtures are hashed in a committed manifest recording the upstream repository and commit, the licence, the MATLAB release, the generating command, the parameters and the seed, and the suite checks the shipped bytes against those hashes. Secondly, the companion document is generated from the manifests and the measured results, with both code panes read from source at render time, so it cannot drift from what was actually run. Finally, we treat the reference itself as re-clonable rather than vendored, and the extraction is reproducible from an upstream clone in one command.

A collaborator joining this work would find a core that is settled and graded, an interface documented with a lifecycle stage per export, and open work concentrated in the four questions above.

## where the direct form loses it. At ratio 1 + 1e-12 the direct expression
